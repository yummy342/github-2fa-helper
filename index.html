密钥在哪找
  1. 登录 GitHub，进 Settings → Password and authentication。
  2. 找到 Two-factor authentication，点 Enable，选 Authenticator app。
  3. 页面会显示一个二维码。二维码下方有一行小字 enter this text code instead，点开它。
  4. 里面会露出一串 32 位大写字母和数字，形如 JBSWY3DPEHPK3PXP...。这正是需要的密钥，复制它。
  5. 粘到上面的输入框，这里就会开始出码。回到 GitHub 把那 6 位数填进去， 完成绑定。

如果用的是手机浏览器又没法复制，可以先把那页截图，回头在电脑上照着敲。 敲完留意下面显示的密钥长度：GitHub 固定 32 个字符，对不上就是敲错了。

为什么不能直接扫码

GitHub 的二维码里装的是一个 otpauth:// 链接，需要手机上有一个 验证器应用来接管它。

国内安卓的麻烦在于：Google 服务不可用，Google Authenticator 装不上； 相机或扫码工具识别出这个链接之后，找不到能处理它的应用，于是没有任何反应。

这台页面绕开这一步——不用扫码，直接吃那串文本密钥。

恢复码一定要存

设置 2FA 的最后一步，GitHub 会给出 16 个恢复码。这是整件事里最容易被 忽略、也最要命的一步。

手机丢了、系统重装、密钥没备份——这时唯一能把账号救回来的东西就是它。 没有恢复码，只能走 GitHub 支持工单人工申诉，国内用户在这条路上成功率很低， 折腾几周也可能拿不回来。

  • 存进密码管理器（Bitwarden、1Password 都行）
  • 或者打印出来、抄到纸上，和重要证件放一起
  • 别只存在那台要装验证器的手机里
这东西能长期用吗

不能。它只解决"设置这一步走不过去"的问题。

密钥只存在浏览器内存里，关掉页面或刷新就没了，这是刻意的设计—— 网页不该成为你账号的长期钥匙保管人。所以它是应急和过渡用的。

设置完成后，长期方案是落到一个真正的验证器上：

  • 安卓：Aegis 或 FreeOTP，可以从 F-Droid 或项目的 GitHub Releases 直接下 APK，不需要 Google Play
  • iOS：App Store 里的任意验证器，包括微软 Authenticator，这条路没有障碍
  • 电脑：KeePassXC、WinAuth
  • 密码管理器：Bitwarden、1Password、KeePassXC 都自带 TOTP，可以把密钥和密码存一起

把同一串密钥填进那些应用，就能长期出码。同一密钥可以同时存在于多处， 互不影响。

安全性说明
  • 页面不发起任何网络请求。顶部的 CSP 策略是 default-src 'none'，浏览器层面禁掉了全部外部资源， 你可以按 F12 在控制台确认。
  • 验证码在本地算出来，密钥和计算过程都不会离开这台机器。
  • 计算用的是自己实现的 SHA-1 和 HMAC，没有依赖 crypto.subtle——那个 API 在 file:// 和部分国产内置浏览器里不可靠。
  • 建议断网之后再粘贴密钥，彻底排除顾虑。
  • 更谨慎的话，把这份 index.html 存到本地，双击打开， 连服务器都不经过。
  • 页面上会显示本机时间。验证码依赖本机时钟，时间偏了所有码都会错 而且没有任何提示，露出时间是为了让你有机会自己发现。
