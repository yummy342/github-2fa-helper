# GitHub 2FA 离线验证码生成器

一个单文件网页，帮国内用户过掉 GitHub 强制 2FA 那道坎。

下载 `index.html`，双击打开，粘贴密钥，出码。不需要联网，不需要安装，不需要服务器。

---

## 解决什么问题

GitHub 从 2023 年起分批强制所有贡献者开启双因素认证。对国内用户来说，这一步经常走不下去。

官方推荐的路径是拿手机扫二维码，装 Google Authenticator。而国内的实际情况是：Google Play 不可用，Google Authenticator 装不上；手机相机识别出 `otpauth://` 链接之后，系统里找不到能接管它的应用，屏幕上一动不动。

于是很多人卡在这里，账号设不下去。

这个工具绕开扫码这一步，直接吃 GitHub 页面上那串文本密钥。

## 怎么用

1. 打开 `index.html`。可以用在线托管版本，也可以下载到本地双击打开。
2. GitHub → `Settings` → `Password and authentication` → `Two-factor authentication` → `Enable` → 选 `Authenticator app`。
3. 页面上会出现一个二维码。二维码**下方**有一行小字 `enter this text code instead`，点开它。
4. 里面会露出一串 32 位大写字母和数字，形如 `JBSWY3DPEHPK3PXP...`。复制它。
5. 粘进工具的输入框，页面开始出 6 位验证码。
6. 回到 GitHub 把验证码填进去，完成绑定。

## 恢复码一定要存

设置 2FA 的最后一步，GitHub 会给出 **16 个恢复码**。这是整件事里最容易被跳过、也最要命的一步。

手机丢了、系统重装、密钥没备份——这时候唯一能把账号救回来的东西就是它。没有恢复码，只能走 GitHub 支持工单人工申诉，国内用户在这条路上成功率很低，折腾几周也可能拿不回来。

- 存进密码管理器（Bitwarden、1Password 都行）
- 或者打印出来、抄到纸上，和重要证件放一起
- 别只存在那台要装验证器的手机里

## 这东西不能长期用

它只负责把「设置这一步」走通。

密钥只存在浏览器内存里，关掉或刷新就没了。这是刻意的——网页不该成为账号的长期钥匙保管人。

设置完成之后，把同一串密钥填进一个真正的验证器：

| 平台 | 推荐 |
| --- | --- |
| 安卓 | **Aegis**、**FreeOTP** — 从 F-Droid 或项目 GitHub Releases 直接下 APK，不需要 Google Play |
| iOS | App Store 里任意验证器，包括微软 Authenticator，这条路没有障碍 |
| 桌面 | **KeePassXC**、**WinAuth** |
| 密码管理器 | Bitwarden、1Password、KeePassXC 都自带 TOTP，可以和密码存一起 |

同一串密钥可以同时存在于多个地方，互相不影响。工具页面上有对应的引导段落。

## 安全设计

- **不联网。** 页面的 CSP 策略是 `default-src 'none'`，浏览器层面禁掉了全部外部资源。按 F12 打开控制台，不会看到任何请求。
- **密钥不出浏览器。** 验证码在本地算出来，输入的内容和计算过程都不离开这台机器。
- **不依赖 `crypto.subtle`。** SHA-1 和 HMAC 是自己实现的纯 JS 版本。Web Crypto 需要安全上下文，在 `file://` 协议和部分国产内置浏览器里判定不一致，用它会直接让工具失效。
- **建议断网使用。** 彻底排除顾虑。

## 自己验一遍

核心算法有测试，用 Node 内置的 OpenSSL 实现做对照，再叠加 RFC 6238 官方测试向量。

```bash
node test/verify.mjs
```

覆盖范围：SHA-1（含填充边界 55/56/64 字节）、HMAC-SHA1（含密钥超 64 字节分支）、Base32 解码、TOTP 动态截断、输入解析。除固定向量外还有大量随机对照。

测试直接读取 `index.html` 里标记的核心算法段，测的就是发布的那份代码，不存在另抄一份的问题。

## 部署成网页

想放到 GitHub Pages 的话，仓库设置里开启 Pages，源选 `main` 分支根目录即可。单文件无依赖，不需要构建步骤。
